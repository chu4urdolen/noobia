# Iris 0.3.0 and TIME_NOW — 2026-09-22

Flashed the verified `build/iris-0.3.0` images through the CH340 UART port.
Esptool identified ESP32-S3 revision 0.2, MAC `30:ed:a0:0c:7e:98`, and verified
all written image hashes.

Live results:

- BLE `PING` passed; `INFO` reported firmware `0.3.0`, protocol 1, VM 1.
- Direct `TIME_NOW` returned monotonic millisecond values with `wrap_bits=32`.
- Loaded `programs/time_now.hex` over BLE: 6 bytes, execution halted at PC 6,
  and register 0 contained the sampled monotonic time.
- UART `CAPS` reported `TIME_MONOTONIC` and `1:TIME_NOW`.
- `CAPS` did not contain I2C or OLED. Explicit calls to `I2C_SCAN` and
  `OLED_TEST` both returned `ERR NO_FUNCTION`.
- A final BLE `PING` passed after VM execution.

Known host/transport issue: the full `CAPS` response succeeds over UART but the
current BLE reply path cannot carry or assemble that long frame; `irisctl caps`
times out. Short BLE request/reply commands, including VM control and
`TIME_NOW`, work normally.
